## 分区聚合核心流程

### 1. 数据准备：获取测点配置

[TdengineZoneAggService.rebuildZoneAggTables](file:///d:/Project/nest-admin/server/apps/micro-data-integration/src/tdengine/tdengine-zone-agg.service.ts#L50-L73) 首先从 MySQL 读取分区与测点的关联配置：

```typescript
// WaterZoneMetricCalcEntity：分区-指标类型-测点 的配置关系
const rows = await zoneMetricRep.find({ where: { zoneCode, metricType, delFlag: '0' } });
configs = rows.map(r => ({ pointCode: r.pointCode, calcSign: r.calcSign }));
```

其中 `calcSign` 是计算符号（+1 或 -1），用于区分正负流向（如进水/出水）。

### 2. 构建测点→设备映射

由于聚合数据表 `meters_5m` 中存的是 `point_code`，需要查 Map 获取对应的 `device_code`：

```typescript
const points = await pointRep.find({ where: { code: In(pointCodes) } });
pointDeviceMap.set(p.code, p.deviceCode);
```

### 3. 多粒度时间窗口对齐

对三种时间粒度（5分钟/1小时/1天）分别处理，时间边界对齐到窗口起点：

```typescript
private alignToWindow(tsMs: number, interval: '5m' | '1h' | '1d'): number {
  if (interval === '5m') {
    return d.minute(Math.floor(minutes / 5) * 5).second(0).millisecond(0).valueOf();
  }
  // 1h: 整点对齐
  // 1d: 零点对齐
}
```

### 4. 核心 SQL：多测点加权聚合

这是分区聚合的**关键 SQL**（[L146-L158](file:///d:/Project/nest-admin/server/apps/micro-data-integration/src/tdengine/tdengine-zone-agg.service.ts#L146-L158)）：

```sql
INSERT INTO water_iot.z_5m_{zone}_{metric}
SELECT 
    ts, 
    ROUND(SUM(diff_val * (
        CASE point_code 
            WHEN 'pointA' THEN 1 
            WHEN 'pointB' THEN -1 
            WHEN 'pointC' THEN 1 
            ELSE 0 
        END
    )), 3) as total_val 
FROM water_iot.meters_5m 
WHERE point_code IN ('pointA', 'pointB', 'pointC') 
  AND ts >= {startMs} AND ts <= {endMs} 
GROUP BY ts
```

**原理**：
- `diff_val` 是测点聚合表中的差值（MAX-MIN）
- `CASE WHEN` 根据 `calcSign` 决定是加还是减
- `SUM` 将多个测点的带符号差值合并为一个分区总量
- 按时间窗口 `GROUP BY ts` 保持时间对齐

### 5. 分区表结构

分区聚合表是 TDengine 的**超级表**，通过 TAGS 标记分区和指标类型：

```sql
CREATE STABLE water_iot.zone_meters_5m (
    ts TIMESTAMP,           -- 时间戳
    total_val DOUBLE       -- 聚合后的总量
) TAGS (
    zone_code NCHAR(100),   -- 分区编码
    metric_type NCHAR(100) -- 指标类型（如 "inlet", "outlet"）
)
```

每个分区+指标组合创建子表：
```sql
CREATE TABLE water_iot.z_5m_zoneA_inlet 
USING water_iot.zone_meters_5m TAGS ('zoneA', 'inlet')
```

## 产销差计算示例

假设分区 A 有：
- 进水口测点 flow_in (calcSign = +1)
- 出水口测点 flow_out (calcSign = -1)

那么 `total_val = SUM(diff_val_flow_in) - SUM(diff_val_flow_out)` = 分区净流量

## 架构总结图

```
设备采集原始数据
    ↓ (流计算自动)
meters_5m/1h/1d (测点聚合: AVG, MAX, MIN, SPREAD, diff)
    ↓ (分区聚合: 加权求和)
zone_meters_5m/1h/1d (分区聚合: total_val)
    ↓
产销差分析 / 区域统计
```

**关键设计**：
1. 利用 TDengine 超级表的 TAGS 分区特性
2. 流计算保证测点聚合实时性
3. 分区聚合是**事后批处理**，通过脏标记触发
4. `CASE WHEN` 实现多测点的加减法组合
