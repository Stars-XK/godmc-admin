## 核心实现机制

### 1. 数据模型（三层超级表）

```
原始数据表 (meters)
    ↓ 流计算自动聚合
测点聚合表 (meters_5m / meters_1h / meters_1d)
    ↓ 分区聚合计算
分区聚合表 (zone_meters_5m / zone_meters_1h / zone_meters_1d)
```

在 [tdengine.service.ts:L61-L109](file:///d:/Project/nest-admin/server/apps/micro-data-integration/src/tdengine/tdengine.service.ts#L61-L109) 初始化时创建了三种聚合粒度的超级表。

### 2. Dirty 标记机制（增量同步关键）

分区数据被标记为"脏"时，会写入 Redis Set：

```
Key: iot:zone_agg:dirty:set
Value: ["zoneCode|metricType", ...]

Key: iot:zone_agg:dirty:range:{zoneCode}|{metricType}
Value: { minTs: timestamp, maxTs: timestamp }
```

### 3. 分区聚合计算逻辑

核心在 [tdengine-zone-agg.service.ts:L50-L170](file:///d:/Project/nest-admin/server/apps/micro-data-integration/src/tdengine/tdengine-zone-agg.service.ts#L50-L170)：

### 4. 调度流程

[TdengineZoneAggScheduler](file:///d:/Project/nest-admin/server/apps/micro-data-integration/src/tdengine/tdengine-zone-agg.scheduler.ts) 每 2 分钟执行一次：

1. 从 Redis 读取所有脏分区标记
2. 批量取出最多 50 个任务
3. 调用 `rebuildZoneAggTables()` 执行分区聚合
4. 成功后从 Redis 移除脏标记

## 与测点级聚合的区别

| 维度 | 测点聚合 (TdengineAggService) | 分区聚合 (TdengineZoneAggService) |
|------|------------------------------|----------------------------------|
| 粒度 | 单设备 + 单测点 | 分区 + 指标类型 |
| 数据源 | 原始表 `meters` | 聚合表 `meters_5m/1h/1d` |
| 聚合方式 | AVG/MAX/MIN/SPREAD | 加权求和 (CASE WHEN) |
| 用途 | 单点数据分析 | 产销差/区域统计 |

---

这种设计通过**流计算自动聚合** + **脏标记触发增量同步** + **多粒度时间窗口** 的组合，实现了高效的分区时序数据管理。
